# Lane grading checklist

Copy this file per lane, fill in the boxes, keep the filled copy in the lane's review issue.
A lane is **S** when every box in sections A and B is ticked. It is **S+** only when A through F are
all ticked, including the numeric floors in D.

Grades below S: **A** = one or two unticked boxes in B; **B** = the lane verifier passes but the lane
is missing a whole surface.

## A. Lane contract (hard gates, all machine-checked)

- [ ] `<lane>/bench/tasks.json` exists, `version: 1`, `corpus: atelier-bench-corpus`, `lane` set.
- [ ] Lane verifier exits 0 and every needle resolves to exactly one line.
- [ ] `--lint` passes: every source file parses, and `fixtures/broken-syntax/*` still refuses to parse.
- [ ] Verifier output on `bench/conformance/` is byte-identical to `bench/conformance/expected.txt`.
- [ ] `node bench/check-matrix.mjs` green, with `bench/matrix.json` regenerated by `--write`, never by hand.
- [ ] CI has one job for this lane, and it is a required check.
- [ ] Lane README carries a coverage map and a ground-truth row whose task count matches `tasks.json`.
- [ ] Install works from the committed lockfile alone. No network fetch, no secrets, no build step
      the lane README does not name.

```bash
<lane verifier>                      # expect: N OK
<lane verifier> --lint               # expect: exit 0
node bench/check-matrix.mjs          # expect: matrix: OK (<N> canonical ids, <k> lanes)
```

## B. Cross-lane parity

- [ ] Zero missing shared canonical ids: every id carried by three or more lanes is carried here.
- [ ] Every shared id keeps the same `surface` string as in the other lanes.
- [ ] `cardinality` and `multi-parent` ids carry the same `exact_count` as every other lane.
- [ ] The lane's `notes` states the counting rule and defines every `kind` string the lane introduces.
- [ ] The domain matches: same seed numbers, same breadth counts, same HTTP routes, same command and
      job set as the other lanes.
- [ ] No tool name appears anywhere in `tasks.json`.

```bash
python3 -c "import json;m=json.load(open('bench/matrix.json'));print([k for k,v in m['canonical'].items() if '<lane>' not in v['lanes'] and len(v['lanes'])>=3])"
# expect: []
```

## C. Answer-key truth (no gate checks any of this)

The verifier proves a needle is unique. It never proves the answer is right. Every box here is a
human read against the source at the graded SHA.

- [ ] Every `implementation` task: the listed implementors really satisfy the contract, and the count
      matches the counting rule in `notes`.
- [ ] Every `call_hierarchy` task: each named callee is really called from the anchored symbol, and
      each named caller really calls it. Verified by reading both bodies, not by name matching.
- [ ] Every `document_symbol` task: `N` recounted from the file, `min_symbols` equals the rule in
      `notes`, and `must_include` never lists more names than `min_symbols` allows.
- [ ] Every `references` task: call sites counted by hand at least once; `min_references` is a floor
      the current tree actually meets.
- [ ] Every `resolution` task with `must_not_include`: the excluded target is a real look-alike that a
      bare-name matcher would return, not a strawman.
- [ ] Every `hover` `contains` string is byte-identical to the source it quotes, in every lane that
      shares the id. Reword the source, never the answer key.
- [ ] No task's `expect` was adjusted to match a tool's output. The tree is the oracle.

```bash
grep -c 'zero-padded width' */[a-z_]*/support/helpers.*   # cross-lane hover contract, expect :1 each
```

## E. Indexer-surface coverage (S+ only)

A lane earns S+ by scoring what the tools under test actually implement for this language. List the
parsers and servers that exist for the lane's stack, then tick only the ones a task exercises.

- [ ] Every framework route parser shipped for this language has at least one route task
      (`def-route-to-handler` and one lane-local variant).
- [ ] Every ORM, schema, or serialization integration shipped for this language is scored, or its
      absence is written into the lane README as a deliberate gap.
- [ ] The lane exercises the language's known-hard resolution class at least once: dynamic dispatch,
      string-keyed lookup, alias divergence, re-export chain, generated code, conditional compilation.
- [ ] At least one task targets a construct where the indexer is known to be wrong today, so the lane
      measures the gap rather than hiding it.
- [ ] Language-server surfaces (`hover`, `document_symbol`, `call_hierarchy`, `implementation`) are
      scored against the server the lane's stack actually starts, not assumed from another lane.

## F. Guards for what no gate catches (S+ only)

Each item below is a defect class this corpus has already shipped once. A lane is S+ only when a
committed test, not a habit, prevents the repeat.

- [ ] A test resolves every module specifier written anywhere in the lane, including type-only and
      docblock-only specifiers.
- [ ] Fixtures whose bytes are the point (CRLF, BOM, mixed endings) carry a `.gitattributes` override
      and a test asserting the bytes survived.
- [ ] Any cross-lane string contract quoted in an `expect` is grep-guarded in every lane that shares it.
- [ ] Task ids are unique, and adding one is proven to fail `check-matrix` until `--write` runs.
- [ ] The lane's own tests exercise every file the lane adds, so a file cannot be silently wrong while
      the acceptance commands stay green.

## Scoring

| Grade | Rule |
| --- | --- |
| S+ | A, B, C, D, E, F all ticked |
| S | A and B ticked, C spot-checked |
| A | one or two boxes unticked in B |
| B | verifier green, a whole surface missing |
| C | verifier green only |
